## 1 am_liam
You want to show several AI apps on Postgres. Each one needs sign-in, a model gateway, secrets, and a database. And you do not want weeks of plumbing first.

Here are three labels: platform, reference scaffolding, and sample apps. The platform is EDB Postgres on AgentPG. That is what we are showing.

Reference scaffolding is identity, the LLM gateway, the kit vault, ecoctl, and an Ansible recipe. All of it is swappable. Use any OIDC provider that sends the roles the apps expect. Any OpenAI-compatible gateway. Your own vault, through the kit. Your own automation.

The sample apps are TrustDesk, PagerLens, CityPulse with its simulator, PayBroker, and ShopFront. They exist to show the platform.

The data is synthetic, and the cards are test cards. We will plan a deployment, see two ways to run it, and watch the apps work.

## 2 af_heart
First, what you need.

The AgentPG command line tool, logged in. Then uv, with Python 3.11. And public container images.

Install ecoctl in two commands. Then run validate.

It lists eight apps after identity, with the gateway first, because the others depend on it. The PagerLens agent is only registered. It runs outside AgentPG.

## 3 am_eric
Now the manifest: the whole fleet, in one file. Each app has a name, its database extensions, and its roles.

Exposes lists the scopes an app offers. Calls lists the scopes it may ask of other apps.

CityPulse may call PagerLens, and nothing else. A typo here fails validation, not production.

Uses gives an app another app's address, with no scope. The simulator uses PayBroker, with a merchant key.

And llm true wires an app to the gateway.

Secrets never appear here. A name that looks like a secret is refused. List it under generate, and ecoctl creates the value.

Groups at the bottom map people to roles across the fleet. So access is one line, not a round of clicking.

## 4 af_heart
Before anything runs, ask for a plan.

Asking for TrustDesk alone pulls in what it needs: the identity provider, and the gateway.

The plan lists every real command and every identity call. Secrets are masked.

Each app is registered for sign-on, gets its own gateway key, then a database and a sandbox.

Last, its sign-in points at its real address, and two access groups are set.

Plan changes nothing, and calls nothing. Run it as often as you like.

## 5 am_liam
Now, applying. Without execute, apply is the same dry run, and it ends by saying nothing was changed.

Add execute, and it shows the plan, then asks before it spends anything on your account.

[pause 1.5]

We answer no, and nothing is created.

Apply is safe to run again. It finds what exists by name, and never rotates a secret unless you ask.

If a step fails, progress is saved. Run the same command again.

Everything is named after the fleet prefix, so one account can hold several fleets.

## 6 af_heart
Some teams deploy with Ansible, not with ecoctl. So there is a recipe for that. It reads the same manifest, and it is yours to own.

Three playbooks. Site creates the fleet. Verify checks it. Destroy removes it.

Offline, all three pass a syntax check.

Destroy is guarded. It refuses unless you pass the fleet name as the confirmation. It deletes exact names only, never a prefix match.

On the platform, we ran it for real, on a throwaway fleet. A complete apply of all eight apps, from empty, in one run: fourteen minutes, no failures.

A second run changed nothing. Verify passed: all eight sandboxes healthy, the gateway clients answering, masking drift zero. The dry run and the teardown are verified too. The guarded destroy returned the account to where it started, with the real fleet untouched.

Not verified: the hosts target on real hosts, and recreate on a real fleet.

## 7 am_eric
Now what apply with execute does, in order. This part is described, not replayed.

Identity comes first, because its address is the issuer every app trusts. Then the gateway. Then each app, with its own gateway key and limits.

Secrets live in one private file next to the manifest. It is the only copy, so back it up.

Status is the check you will use most. Every app answers health and readiness, each gateway client works, and the identity registry matches. Exit code zero means green.

The one manual step is you. Create yourself in the identity console, join the admin group, and open the launcher: one tile per app, one sign-in.

## 11 am_eric
Last, the platform itself. Every app has a Database page, fed by the EDB extensions.

Top queries come from edb_stat_monitor. Settings suggestions come from edb_pg_tuner. Index suggestions come from query_advisor.

These are suggestions only. A person decides what to change.

And AI access to the database goes through a read-only user, with masked columns.

PayBroker has the same page. Its monitor shows the masking the kit applied: revoked tables, and masked views.

From the command line, ecoctl insights lists the advisor's suggestions for every app.

Two MCP routes exist: each app's own MCP server, and AgentPG's database MCP. The guide compares them.

## 12 af_heart
To wrap up: when you ship a new image, you recreate the app.

A sandbox's address contains its id. So apps that depend on it are recreated too, and the connection is repaired.

ecoctl lists that cascade, and asks first.

[pause 1.2]

We answer no, and nothing is deleted.

That is the loop. One manifest, one state file, one guide.

Add an app with a few lines. Rotating every secret is one flag, then a recreate. The state file is your backup target.
